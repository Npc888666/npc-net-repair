## 这是什么

一句话：**当你的电脑“明明连着网，但就是上不了网”时，用它。**

很多 AI 工具、代理软件、抓包工具、加速器、逆向调试环境，为了让自己工作，会悄悄改掉本机的网络配置：把系统代理指到 `127.0.0.1:7890`、往 `hosts` 里钉死域名、重置 Winsock、把 DNS 改成不存在的地址、给网卡写死一个静态 IP、留下端口转发规则……**它们卸载或退出时并不会把这些改回来**，于是你的网络就“废”了。

这个工具做的事情很朴素：**在动手前完整备份，然后把被改坏的网络配置逐层恢复成正常状态，最后验证一遍是否真能上网。**

- 面向普通用户：双击 → 点“是” → 等它跑完。
- 面向技术用户：一个 PowerShell 引擎，带 `-DryRun`、`-Deep`、`-RestoreHosts` 等参数，可脚本化。
- 面向所有场景：**不重启、不安装、不留后台、不收集数据。**

> 适用场景：个人电脑、测试机、抓包/逆向实验机、被 AI 编程助手或代理工具折腾过的开发机。
> 公司/学校统一管理的设备，请先确认管理员策略允许修改网络设置。

## 它治哪些“疑难杂症”

| 症状 | 通常的原因 | 本工具的处理 |
| --- | --- | --- |
| 连上 WiFi，浏览器打不开网页 | 系统代理被设成 `127.0.0.1:xxxx`，代理软件已退出 | 关闭 WinINET/WinHTTP 代理，清理代理环境变量 |
| 右下角黄色感叹号“无 Internet” | NCSI 探针被改坏 / 探测被防火墙拦截 | 重建 NCSI 注册表、恢复主动探测、重启 `NlaSvc` |
| 只有某些网站打不开 | `hosts` 被写入劫持记录 | 只保留标准本机条目，其余劫持行全部清除 |
| 微信能用，浏览器打不开网页 | 浏览器走系统代理，其他程序不走 | 同上，代理与 Winsock 一起修 |
| 装完/卸载完 AI 工具、加速器、抓包软件后彻底断网 | Winsock LSP 被替换、TCP/IP 栈被改 | `winsock reset` + `int ip/tcp/ipv4/ipv6 reset` |
| 卡在 `169.254.x.x`，拿不到地址 | 网卡被写死静态 IP / DHCP 客户端异常 | 检测到地址层异常才切回 DHCP，并续租 |
| 能 ping 通 IP，但域名全解析失败 | DNS 被篡改 / NRPT 策略残留 | DNS 改回自动获取，深度模式清理 NRPT |
| 网卡属性里 IPv4 被取消勾选 | 协议绑定被关闭 | 重新启用 IPv4/IPv6 绑定 |
| 某些流量被莫名其妙劫走 | `netsh portproxy` 残留转发规则 | 清空 portproxy 规则 |
| 重启才好，但不想重启 | Winsock/TCPIP 重置需要重新加载驱动栈 | 用网卡重载替代重启（见[原理](#原理为什么可以不用重启)） |

## 功能特性

- **一键修复**：双击 exe，点一次“开始修复”，剩下的全自动。无需记命令、无需看懂日志。
- **无需重启**：核心卖点。通过“禁用网卡 → 等待 → 启用网卡”触发 PnP 重新加载 TCP/IP 驱动栈，再配合关键服务重启，替代“必须重启才生效”的传统做法。
- **专治 AI 工具留下的烂摊子**：代理劫持、hosts 污染、Winsock 损坏、DNS 篡改、静态 IP 写死、NCSI 异常、端口转发残留、协议绑定被关、路由异常，九类问题一次扫干净。
- **10 阶段修复 + 第二轮自动补救**：第一轮跑完会真实验证连通性；如果还不通，自动追加 DNS 策略清理、公共 DNS 兜底、协议栈二次重置、服务二次重启、重新续租。
- **动手前全量备份**：hosts 原文件、代理注册表、每块网卡的 IP/DNS 配置（JSON）、无线配置文件，全部落到 `C:\ProgramData\NpcNetRepair\backup_时间戳\`，随时可回滚。
- **静态 IP 保护**：默认只在“地址层真的坏了”（无地址 / `169.254.*` / 网关为空）时才切 DHCP；`-KeepStaticIP` 可以强制只修 DNS 和路由，绝不动 IP。
- **远程会话保护**：检测到 RDP/SSH 会话时自动跳过网卡重载，避免把你踢下线。
- **中英文自动切换**：按系统语言显示，中文系统中文界面，英文系统英文界面。
- **单文件、免安装、无后台**：exe 自包含；跑完即退，不注册服务、不开机自启、不驻留进程。
- **可回滚**：图形界面有“回滚设置”按钮，命令行有 `-RestoreHosts` / `-RestoreConfig`。

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11（推荐）；Windows 7 / 8 需 PowerShell 5.1 + .NET Framework 4.6+ |
| 权限 | **必须管理员**（修改网络配置属于系统级操作） |
| 依赖 | 无。无需安装 Python / Node / .NET SDK |
| 耗时 | 约 30–90 秒 |
| 副作用 | 修复过程中网卡会重启一次，**断网约 4–8 秒**，属正常现象 |

### 方式一：单文件 exe（推荐，普通用户）

1. 下载 `Npc修复网络.exe`（仓库里的文件名），或从 [Releases](https://github.com/Npc888666/npc-net-repair/releases/latest) 下载 `NpcNetRepair.exe`——两者是同一个程序。放在任意文件夹都行，**无需解压，无需其它文件**。
2. 双击运行。
3. Windows 弹出“是否允许此应用对你的设备进行更改？”→ 点 **是**。
4. 窗口出现后，点 **开始修复**（窗口刚弹出约 0.9 秒内点击无效，是防误触设计）。
5. 等它跑完。中途断网几秒不用管，最后会提示“网络已恢复”。
6. 关闭窗口，重新打开浏览器测试。

> exe 已内嵌图形界面与修复引擎，单独一个文件即可运行。

### 方式二：脚本三件套（备用，exe 打不开时用）

把下面三个文件放在**同一个文件夹**里：

```text

Npc修复网络-GUI.ps1      ← 图形界面（bat 自动调用）
Npc修复网络.ps1          ← 核心修复引擎
```

右键 `Npc修复网络.bat` → **以管理员身份运行**。图形界面起不来时会自动降级为黑底白字的控制台模式，修复效果一致。

### 方式三：命令行（技术用户 / 批处理集成）

```powershell
# 以管理员身份打开 PowerShell，进入项目目录
powershell -NoProfile -ExecutionPolicy Bypass -File .\Npc修复网络.ps1

# 只看不改，先演习一遍
powershell -NoProfile -ExecutionPolicy Bypass -File .\Npc修复网络.ps1 -DryRun

# 无人值守：不询问、不暂停

# 只回滚 hosts
powershell -NoProfile -ExecutionPolicy Bypass -File .\Npc修复网络.ps1 -RestoreHosts

# 只回滚网卡 IP/DNS
powershell -NoProfile -ExecutionPolicy Bypass -File .\Npc修复网络.ps1 -RestoreConfig
```

## 修复流程：10 个阶段

| # | 阶段 | 做什么 |
| --- | --- | --- |
| 1 | 全量备份 | hosts、代理注册表、每块网卡 IP/DNS（JSON）、无线配置 |
| 2 | 代理劫持清理 | 关 WinINET 代理、`winhttp reset proxy`、清 `HTTP_PROXY` 等环境变量、清 portproxy 转发、深度模式清 NRPT |
| 3 | hosts 去污染 | 只保留 `localhost` 等标准条目，其余劫持行移除并单独存档；原子写入，避免写坏 hosts |
| 4 | 协议栈重置 | `winsock reset catalog`、`int ip/ipv4/ipv6/tcp reset`、TCP 全局参数归位、恢复 IPv6 默认组件、深度模式重置防火墙 |
| 5 | 网卡启用 + 协议绑定 | 启用被禁用的网卡、恢复 IPv4/IPv6 绑定、关闭网卡节能断流 |
| 6 | IP / DNS / 路由归位 | DNS 改自动获取；地址层异常才切 DHCP；MTU 回 1500；跃点自动；清 ARP；清除异常默认路由 |
| 7 | 关键服务重启 | `Dnscache`、`Dhcp`、`NlaSvc`、`netprofm`、`WlanSvc`、`nsi` |
| 8 | 网卡重载 | 禁用 → 等待 → 启用，触发 TCP/IP 驱动栈重新加载（**免重启的关键**） |
| 9 | 续租 / 注册 / 重连 | `ipconfig /release`、`/renew`、`/flushdns`、`/registerdns`，无线自动重连 |
| 10 | NCSI 探针修复 | 重建 NCSI 注册表、开启主动探测、清理阻挡探测的防火墙规则、重启 `NlaSvc` |

跑完第 10 步后，会做一轮**真实验证**：IP/网关、网关 ping、公网 ICMP、DNS 解析、TCP 443、HTTP 探针、代理是否已关闭。
若仍不通，自动进入**第二轮深度补救**：清 DNS 策略、公共 DNS 兜底（223.5.5.5 / 119.29.29.29）、协议栈二次重置、服务二次重启、再次续租与刷新。

## 高级参数

| 参数 | 作用 |
| --- | --- |
| `-DryRun` | 演习模式：只打印将要做什么，不修改任何配置 |
| `-Deep` | 深度模式：额外重置防火墙、清理 NRPT、处理网络位置 |
| `-ForceDhcp` | 无条件把网卡切回 DHCP（适合确定是静态 IP 被写死的情况） |
| `-KeepStaticIP` | 绝不动 IP 地址，只修代理 / hosts / DNS / 协议栈 |
| `-SkipAdapterReload` | 跳过网卡重载（远程桌面、SSH 会话必用） |
| `-RestoreHosts` | 只从最近一次备份恢复 hosts |
| `-RestoreConfig` | 只从最近一次备份恢复网卡 IP / DNS |
| `-NoPause` | 跑完不等按键，适合批处理 |
| `-Yes` | 不询问，直接开始 |

## 原理：为什么可以不用重启

传统做法是 `netsh winsock reset` + `netsh int ip reset`，然后**重启**。原因是这两条命令改的是注册表里的协议栈配置，而已经加载进内存的 TCP/IP 驱动不会因为注册表变化就重新读取——微软官方文档也是这么写的。

本工具的做法是：**不重启系统，只重启“网络子系统”。**

1. **网卡重载**：禁用目标网卡 → 等待 PnP 完成卸载 → 重新启用。网卡重新枚举时，Windows 会重新加载 TCP/IP 协议驱动，等于一次网络栈冷启动。这一步替代了 95% 以上“必须重启”的场景。
2. **关键服务重启**：`Dnscache`、`Dhcp`、`NlaSvc`、`netprofm`、`nsi` 依次重启，让 DNS 缓存、地址租约、网络位置感知、网络存储接口全部重新初始化。
3. **续租与重连**：`ipconfig /release` → `/renew` 重新走一遍 DHCP；无线网卡重新关联。
4. **最后验证**：不是“跑完就算成功”，而是真的去 ping 网关、解析域名、连 443、拉一个 HTTP 探针，用结果说话。

另外几个工程细节：

- **先备份再动手**：所有改动前先落盘备份，任何一步失败都能回到原样。
- **原子写 hosts**：写临时文件 → 校验 → 覆盖，避免异常 ACL 下把 hosts 截成 0 字节。
- **逐步容错**：每一步独立 `try/catch`，某一步失败只记一笔，不影响后续步骤。
- **环境自适应**：全部走 PowerShell 对象和注册表，不解析本地化文本，所以中文/英文/其它语言系统都能跑；没有 `Get-Net*` cmdlet 的老系统自动降级到 `netsh`。
- **远程会话保护**：检测到 RDP/SSH 就跳过网卡重载，避免修复过程把远程连接掐断。

## 适用与不适用

**能修的（配置层问题）**

- 代理劫持、hosts 污染、DNS 被篡改
- Winsock / TCP/IP 栈损坏
- 静态 IP 被写死、DHCP 拿不到地址
- 网卡被禁用、IPv4 协议绑定被取消
- 路由表异常、默认网关指向 `0.0.0.0`
- 端口转发残留
- “无 Internet”黄色感叹号（NCSI 异常）

**不在修复范围内的（非配置问题）**

- 网线没插、WiFi 开关关了
- 网卡驱动损坏、网卡硬件故障
- 路由器断电、光猫故障、宽带欠费
- 公司/学校网络需要账号认证（这类要先打开浏览器走登录页）
- 系统文件损坏

**快速判断**：能看到“已连接但打不开网页”或黄色感叹号 → 大概率能修；图标带红叉、或根本看不到网络图标 → 物理/驱动问题，工具只能尽力。

## 常见问题

**Q：会不会把电脑搞坏？**
不会。它只把网络设置恢复成 Windows 默认状态，而且动手前完整备份，随时能还原。

**Q：会不会删我的文件？**
不会。只碰网络配置，不碰文档、照片、软件。

**Q：为什么必须给管理员权限？**
改网络设置是系统级操作，普通权限动不到这些设置。这个弹窗是 Windows 标准提示，任何修网络的工具都会弹。

**Q：真的不用重启？**
不用。用网卡重载 + 服务重启替代系统重启，修完立即生效。少数驱动异常顽固的机器，可能仍需手动重启一次。

**Q：我是静态 IP（公司固定 IP），会被改成自动获取吗？**
默认不会。程序先探测地址层，只有真的坏了（无地址 / `169.254.*` / 无网关）才切 DHCP。需要绝对保险就加 `-KeepStaticIP`。

**Q：英文系统能用吗？**
能。按系统语言自动切换中/英文界面。

**Q：一打开就会自动改网络吗？**
不会。必须手动点“开始修复”，且窗口出现后 0.9 秒内的点击会被忽略，防手抖误触。

**Q：跑完还是上不了网？**
1. 把浏览器全部关掉重开（浏览器启动时才读代理设置）。
2. WiFi 关了再开，或网线拔插一次，等 10 秒。
3. 手机连同一个 WiFi 试试：手机也不行 → 路由器/宽带问题；手机行 → 电脑问题，再跑一次（会自动进入深度补救）。

**Q：怎么卸载？**
不用卸载。删掉 exe，再删 `C:\ProgramData\NpcNetRepair` 即可。没有服务、没有自启、没有残留进程。
